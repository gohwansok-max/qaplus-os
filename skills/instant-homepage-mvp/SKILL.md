# Instant Homepage MVP Skill

## 목적
사용자가 "홈페이지 만들어줘", "업체 홈페이지 MVP 만들어줘", "HTML로 만들어줘", "GitHub Pages에 올릴 홈페이지 만들어줘"라고 요청하면 설명만 하지 말고 **바로 실행 가능한 결과물**을 만든다.

기본 목표는 다음과 같다.

- 첫 요청에서 바로 눈에 보이는 MVP 제공
- 모바일/PC 반응형
- 실제 영업에 쓸 수 있는 CTA 중심 구조
- GitHub Pages에서 바로 배포 가능
- 단순 데모가 아니라 업체명·전화번호·지역 등을 쉽게 수정 가능
- 사용자가 이후 CSS/UI/UX 의견을 주면 같은 결과물을 계속 개선

## 답변 첫 줄
이 스킬을 사용했다면 항상 첫 줄에 다음을 표시한다.

`사용 스킬: instant-homepage-mvp`

## 핵심 동작 원칙

### 1. 질문보다 초안 우선
사업 종류와 핵심 서비스가 파악되면 추가 질문 없이 합리적인 기본값으로 MVP를 먼저 만든다.

다만 다음이 실제 운영에 영향을 주면 임시값을 사용하고 마지막에 명시한다.

- 업체명
- 대표자명
- 전화번호
- 영업지역
- 실제 가격
- 인증/수치/성능 주장
- 사업자등록 정보

### 2. 기존 자산 우선
사용자가 기존 HTML, CSS, 이미지, 브로슈어, 로고, 웹사이트를 제공하면 이를 먼저 확인한다.

- 기존 홈페이지가 있으면 새 프로젝트를 만들지 말고 수정·확장한다.
- 기존 UI 구조가 쓸 만하면 유지한다.
- 같은 기능을 이름만 바꿔 중복 생성하지 않는다.

### 3. 기본 홈페이지 구조
별도 요구가 없으면 다음 순서로 구성한다.

1. 상단 공지/신뢰 문구
2. Sticky 네비게이션
3. Hero
   - 핵심 가치제안
   - 전화/문의 CTA
   - 신뢰 포인트 3개
4. 서비스 카드
5. 제품 또는 특별 서비스 소개
6. 차별점/서비스 원칙
7. 이용 절차
8. 설치사례/포트폴리오/후기
9. 문의 영역
10. Footer
11. 모바일 고정 CTA

사업 특성에 따라 불필요한 섹션은 제거한다.

### 4. 영업형 UX 기본값
업체 홈페이지는 예쁜 것보다 문의 전환이 우선이다.

기본 UX:

- 첫 화면 안에 무엇을 하는 업체인지 즉시 이해
- 전화 버튼을 첫 화면과 모바일 하단에 배치
- 고객이 자주 걱정하는 비용·과잉수리·출장·A/S 등의 불안을 문구로 해소
- 서비스명을 고객이 검색하는 단어로 작성
- 긴 설명보다 카드/배지/절차 형태를 활용
- 문의폼은 4~6개 필드 이내
- 서버가 없는 MVP에서는 `tel:` 또는 `sms:` 연결 사용

### 5. HTML 기본 규격
기본 결과물은 `index.html`이다.

- HTML5
- UTF-8
- CSS/JS 포함
- 외부 프레임워크 없이도 동작 가능
- 반응형 레이아웃
- 모바일 우선 확인
- SEO용 title/description
- 접근성을 위한 `alt`, `label`, 의미 있는 섹션 구조
- 설정값은 JS `CONFIG` 한 곳에서 바꾸도록 설계

예:

```js
const CONFIG = {
  BUSINESS_NAME: "업체명",
  OWNER: "대표자",
  PHONE_DISPLAY: "010-0000-0000",
  PHONE_LINK: "01000000000",
  REGION: "영업지역"
};
```

### 6. 이미지 처리 규칙
이미지 때문에 홈페이지가 깨지는 일이 없도록 반드시 검증한다.

우선순위:

1. 사용자가 단일 HTML을 원하거나 파일 전달 편의가 중요함
   - 이미지를 Base64/Data URI로 HTML 내부에 임베드
2. 일반적인 GitHub Pages 프로젝트
   - `assets/` 폴더 사용
   - ZIP에 HTML과 assets를 함께 포함
3. 외부 URL 의존은 사용자가 요청하지 않는 한 피한다.

검증 항목:

- `<img src>` 경로가 실제 존재하는지 확인
- ZIP 안에 이미지가 모두 포함되었는지 확인
- 단일 HTML 버전이면 외부 로컬 이미지 경로가 남지 않았는지 확인
- 가능하면 파일을 직접 열어 렌더링 확인

### 7. 이미지 생성/재디자인
사용자가 브로슈어 사진, 제품 사진, 홍보물을 제공하고 홈페이지용으로 개선해 달라고 하면:

- 사진 속 종이/테이블/왜곡/그림자를 그대로 홈페이지에 쓰지 않는다.
- 원본 정보를 참고해 웹용 배너/카드/설치사례 이미지로 재디자인한다.
- 제품명, 브랜드명, 기능명은 가능한 한 원본과 일치시킨다.
- 법적/기술적 수치 주장은 원본 근거가 없는 경우 임의 추가하지 않는다.
- 생성된 이미지를 실제 HTML에 연결하고 경로를 검증한다.

### 8. 사용자 피드백 반영
사용자가 이후 CSS/UI/UX 의견을 주면 해당 프로젝트의 다음 버전으로 수정한다.

예:

- "좀 더 고급스럽게"
- "네이버 느낌 말고 애플 느낌"
- "전화 버튼이 너무 많다"
- "실제 사업하는 친구 의견 반영해줘"
- "모바일에서 먼저 보이게"

이때 처음부터 다시 만들지 말고 기존 파일을 기준으로 변경한다.

변경 후에는 다음을 간단히 보고한다.

- 무엇을 바꿨는지
- 실제 동작 검증 여부
- 미검증 항목

### 9. GitHub Pages 배포 패키지
사용자가 GitHub Pages를 언급했거나 정적 사이트가 적합하면 기본적으로 다음을 제공한다.

- `index.html`
- 필요한 `assets/`
- `README.md`
- 전체 ZIP

단일 HTML이 더 편한 경우 추가로 standalone 버전을 제공한다.

### 10. 완료 전 검증
"완료"라고 하기 전에 가능한 범위에서 아래를 확인한다.

- HTML 문법상 큰 오류 없음
- 이미지 링크 깨짐 없음
- CTA 링크 존재
- 모바일 미디어쿼리 존재
- 폼 요소 label 존재
- 전화번호/업체명 임시값 여부
- GitHub Pages에서 상대경로 사용 가능
- ZIP 패키지 구조 정상

검증하지 못한 것은 반드시 `미검증`이라고 쓴다.

## 빠른 MVP 기본 디자인

기본 시각 방향:

- 배경: white / very light gray
- 메인 컬러: 업종에 맞는 1개 브랜드 컬러
- 카드: 18~26px radius
- 그림자: 약하게
- 큰 제목: 굵고 짧게
- 본문 최대폭 제한
- 카드 간격 충분히
- 모바일 버튼 높이 48px 이상
- 모바일 화면에서는 1열 우선

사용자가 CSS/UI/UX 방향을 주면 이 기본값보다 사용자 방향을 우선한다.

## 결과물 보고 형식

결과물 생성 후 답변은 짧고 실무적으로 작성한다.

예:

- 수정된 `index.html`
- GitHub Pages용 ZIP
- 주요 반영사항 3~6개
- 검증 결과
- 임시값/확인 필요 사항

## 금지

- 홈페이지 요청에 장황한 기획 설명만 하고 파일을 만들지 않는 것
- 이미지가 없는 상태에서 존재한다고 가정해 경로만 넣는 것
- 사용자가 제공한 기존 홈페이지를 무시하고 새로 만드는 것
- 실제 근거가 없는 인증, 수치, 판매량, 고객사 등을 만들어 넣는 것
- 모바일 레이아웃을 확인하지 않고 PC만 만드는 것
