## 1. 언제 쓰는가

| 상황 | 복원 대상 |
|:---|:---|
| `/forget_all`을 실수로 실행 | 학습 기억 |
| 잘못 학습된 항목이 대량으로 쌓여 이전 상태로 되돌릴 때 | 학습 기억 |
| `기준 삭제`로 필요한 기준을 지웠을 때 | 작업 기준 |

- Worker 롤백(`wrangler rollback`)은 코드만 되돌린다. **기억 데이터(Durable Object)는 그대로 남으므로** 코드 롤백만으로는 기억이 복원되지 않는다.
- 복원하면 백업 시점 이후 학습한 내용과 대화 기록은 사라진다. 그래서 복원 전에 현재 상태를 한 번 더 백업한다(3단계).

## 2. 백업 (정기 · 배포 전)

인증은 PC 에이전트의 `config.json`에 있는 토큰을 쓴다. 토큰은 화면에 출력하지 않는다.

```powershell
$cfg = Get-Content $env:LOCALAPPDATA\JarvisAgent\config.json | ConvertFrom-Json
$h = @{Authorization = "Bearer $($cfg.agentToken)"}
$stamp = Get-Date -Format 'yyyyMMdd-HHmm'
$dir = "$HOME\JarvisBackup"; New-Item -ItemType Directory -Force $dir | Out-Null

# ① 학습 기억
Invoke-RestMethod "$($cfg.workerUrl)/memory" -Headers $h | ConvertTo-Json -Depth 20 | Out-File "$dir\memory-$stamp.json" -Encoding utf8
# ② 작업 기준
Invoke-RestMethod "$($cfg.workerUrl)/memory/standards" -Headers $h | ConvertTo-Json -Depth 20 | Out-File "$dir\standards-$stamp.json" -Encoding utf8

Get-ChildItem $dir | Sort-Object LastWriteTime -Descending | Select-Object -First 2 Name, Length
```

- [ ] 두 파일이 생성되고 크기가 0보다 큰지 확인
- 백업 파일에는 개인 프로필과 대화 일부가 들어 있다. **Git 저장소·공유 폴더에 올리지 않는다.**
- 권장 주기: 배포 전, `/forget_all` 실행 전, 월 1회

## 3. 학습 기억 복원

### 3-1. 사전 조치
- [ ] PC 에이전트 일시 중지 (복원 중 새 학습이 끼어드는 것을 막는다): `Stop-ScheduledTask JarvisAgent`
- [ ] 텔레그램 질문을 잠시 보내지 않는다 (Actions 경로 저장 충돌 방지)
- [ ] **현재 상태 백업**: 2단계 명령 실행 (복원을 되돌릴 때 사용)

### 3-2. 백업 내용 확인

```powershell
$file = "$HOME\JarvisBackup\memory-YYYYMMDD-HHMM.json"   # 복원할 백업 파일로 바꾼다
$backup = Get-Content $file -Raw -Encoding utf8 | ConvertFrom-Json
$count = ($backup.doc.profile.PSObject.Properties | ForEach-Object { @($_.Value).Count } | Measure-Object -Sum).Sum
"백업 rev: $($backup.doc.rev) / 기억 항목: $count / 누적 대화: $($backup.doc.stats.conversations)"
```

- [ ] 기억 항목·누적 대화 수가 복원하려는 시점과 맞는지 확인

### 3-3. 복원 실행

```powershell
$cfg = Get-Content $env:LOCALAPPDATA\JarvisAgent\config.json | ConvertFrom-Json
$h = @{Authorization = "Bearer $($cfg.agentToken)"}
$current = Invoke-RestMethod "$($cfg.workerUrl)/memory" -Headers $h
$body = @{expected_rev = [int]$current.doc.rev; doc = $backup.doc} | ConvertTo-Json -Depth 20 -Compress
Invoke-RestMethod "$($cfg.workerUrl)/memory" -Method Put -Headers $h `
  -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

- 정상: `rev` 숫자가 반환된다. Worker가 rev를 현재값 + 1로 다시 매기므로 백업 rev와 달라도 정상이다.
- `409` 오류: 그 사이 다른 저장이 끼어든 것. 3-3을 다시 실행한다.
- `413` 오류: 256KB 초과. 정상 백업에서는 발생하지 않는다. 파일이 손상됐는지 확인한다.

### 3-4. 확인·재가동
- [ ] 텔레그램 `/memory` → 백업 시점의 항목이 보인다
- [ ] 텔레그램 `/status` → `[기억]` 누적 대화·기억 항목 수가 3-2 결과와 같다
- [ ] PC 에이전트 재가동: `Start-ScheduledTask JarvisAgent` → `/status`에서 `[PC 에이전트] 정상`

## 4. 작업 기준 복원

작업 기준은 `/forget_all`로 지워지지 않는다. `기준 삭제`로 지웠을 때만 복원한다. 한꺼번에 넣는 API는 없으므로 백업 파일에서 **텔레그램에 붙여넣을 메시지**를 만들어 하나씩 보낸다.

```powershell
$file = "$HOME\JarvisBackup\standards-YYYYMMDD-HHMM.json"   # 복원할 백업 파일
$saved = (Get-Content $file -Raw -Encoding utf8 | ConvertFrom-Json).standards
foreach ($s in $saved) { "기준 저장: $($s.name)`n$($s.body)`n`n----------" }
```

- [ ] 출력된 블록을 `----------` 앞까지 하나씩 복사해 Jarvis 텔레그램에 보낸다 (이름이 같으면 덮어쓰기)
- [ ] `/standards` → 개수와 이름이 백업과 같은지 확인

## 5. 복원을 되돌리기

- [ ] 3-1에서 만든 **복원 직전 백업** 파일로 3-2~3-4를 다시 실행한다

## 6. 주의사항

| 항목 | 내용 |
|:---|:---|
| 개인정보 | 백업 파일은 본인 PC에만 보관한다. 메일·메신저·저장소로 옮기지 않는다 |
| 토큰 | `agentToken`은 명령 안에서만 읽고 출력하지 않는다. 화면 캡처에 `config.json` 내용이 나오지 않게 한다 |
| 범위 | 이 절차는 학습 기억과 작업 기준만 다룬다. 페어링 기기·대기 질문·직전 답변(`저장해줘`용)은 복원 대상이 아니다 |
| 페어링 PC | 페어링 기기도 같은 명령을 쓸 수 있다. 단 해당 PC의 `config.json` 토큰이 승인된 상태여야 한다 |
