# 학습 기록 (Lessons Learned)

> AI가 실수하거나 새로운 인사이트를 발견하면 여기에 기록합니다.
> 새 세션 시작 시 이 파일을 먼저 읽어서 같은 실수를 반복하지 않습니다.
>
> **작성 규칙**: 5 Whys로 **근본 원인**까지 파고들 것. 증상 수정 금지.

---

## 근본 원인 클러스터 (Root Cause Clusters)

실수가 누적되면 아래 4개 클러스터 중 하나로 분류하여 패턴을 파악합니다:

- **A. 전제 조건 미확인**: 작업 대상의 현재 상태를 확인하지 않고 추정
- **B. 본질 회피**: 표면 요청만 수용하고 진짜 문제를 파고들지 않음
- **C. 검증 누락**: 결과물을 자체 검수 없이 납품
- **D. 커뮤니케이션 실패**: 확신도/근거/대안 없는 모호한 보고

## Seed 원칙 (2026-08-24 셋업 시 확정)

### [필수] 출처 기반 답변 원칙
- **상황**: HACCP/FSSC22000 컨설팅 사업 — 20년 경력 전문성이 핵심 자산
- **규칙**: 오픈채팅방/블로그/유튜브 모든 답변에 **출처 명시**
- **근거**: 전문성 = 추측이 아닌 근거. 틀린 정보 1건이 신뢰를 무너뜨림
- **적용**: 모르면 "확인 후 알려드릴게요". 추측 답변 절대 금지 (Zero-Inference)
- **클러스터**: A (전제 조건 미확인 방지)

### [필수] 식품/품질관리 전문 용어 한국어 자연 발음(TTS) 규칙
- **상황**: TTS 엔진(Edge-TTS 등)이 영문 약어(HACCP, CCP, SOP, F0, RTD 등)를 알파벳 그대로 어색하게 읽음.
- **규칙**:
  - 화면 자막/텍스트: 전문적인 영문 표기 유지 (`HACCP`, `CCP-B`, `F0값 ≥ 4.0`, `SOP`)
  - 음성 내레이션(TTS 입력): 사전 치환을 통해 현장 자연 발음 적용 (`해썹`, `씨씨피 비`, `에프제로값 이상 4.0`, `에스오피`)
- **클러스터**: D (커뮤니케이션 완성도)

### [필수] 3대 병목에 집중
1. **구독자 정체** — 유튜브 50명에서 멈춤
2. **매출 연결 부재** — 콘텐츠 → 컨설팅 전환 동선 불명확
3. **영상 제작 시간** — 너무 오래 걸림
- **적용**: 모든 제안이 이 3가지 중 하나를 해소하는지 자문. 아니면 우선순위 후순위
- **클러스터**: B (본질 회피 방지)

## 기록

### 2026-04-08 — [A] 작업 대상의 배포 상태 미확인 후 잘못된 전제로 계획 수립

- **상황**: ai-ceo-os 레포 업그레이드 제안 시, "부트캠프 1기 수강생이 지금 이 레포를 받고 있다"는 가정으로 "공사 중 노출 리스크"를 근거로 스코프 축소를 제안.
- **CEO 정정**: "아직 배포 전"
- **잘못된 판단**: 배포 상태를 확인하지 않고 본사 부트캠프 일정에서 유추. 추정을 사실처럼 사용.
- **5 Whys 근본 원인**:
  1. 왜 잘못된 전제를 세웠나? → 본사 맥락(부트캠프 1기 운영 중)을 프로젝트 상태로 투사
  2. 왜 투사했나? → 작업 대상(ai-ceo-os)과 본사(에이나우)를 동일한 컨텍스트로 취급
  3. 왜 구분하지 못했나? → 작업 시작 전 "이 프로젝트는 지금 어떤 단계인가?" 질문을 스킵
  4. 왜 스킵했나? → 브리핑 단계에서 tasks/todo.md는 읽었지만, **레포 상태(배포됨/배포 전/폐기)를 따로 확인하는 체크포인트가 없었음**
  5. 왜 체크포인트가 없었나? → 세션 시작 프로토콜에 "대상 프로젝트의 현재 상태 확인" 단계가 빠져 있음

- **교훈**: 작업 대상의 상태 정보(배포 여부, 활성 사용자 여부, 버전 단계)를 **작업 판단 전에 반드시 1회 확인**할 것.

- **향후 적용 규칙**:
  1. 프로젝트성 작업을 시작할 때 **"이 프로젝트의 현재 상태는 무엇인가?"**를 체크리스트 최상단에 고정
  2. 상태를 추정할 수밖에 없는 경우 **"추정 전제: X"를 명시**하고 확신도 하향 조정
  3. 타이밍/노출/배포 리스크를 근거로 내세울 때는 반드시 **상태 확인을 선행**

- **클러스터**: A (전제 조건 미확인)

### 2026-08-25 — [C] 동적 토픽 수신 시 정적 템플릿 미분기 버그 수정 및 전문 도메인 B-Roll 연동

- **상황**: 사용자가 텔레그램으로 임의 주제(`/make [주제]`) 입력 시, 제목만 바뀌고 씬 2~5의 대본과 이미지가 고정 템플릿으로 출력됨.
- **5 Whys 근본 원인**:
  1. 왜 내용이 동일했나? → `generate_dynamic_scenes_for_custom_topic` 함수가 고정 문구 템플릿을 반환함
  2. 왜 고정 문구로 작성되었나? → 초기 프로토타입 작성 시 토픽별 키워드 분기 및 LLM 연동 레이어가 생략됨
  3. 왜 생략되었나? → 파이프라인 연결 테스트에 집중하느라 실제 도메인 지식 생성 엔진 고도화가 후순위로 밀림
  4. 개선 조치:
     - 12대 HACCP/식품품질관리 전문 카테고리(스마트HACCP, 가열살균, 냉각, 알레르기, 소비기한, 미생물 등) 키워드 시맨틱 분석 엔진 탑재
     - 카테고리별 초고화질 포토리얼리스틱 B-Roll 이미지 에셋(레토르트, 동결터널, 알레르기 ATP 스왑, 클린룸 랩 등) 연동
     - Claude / ChatGPT LLM API 키 설정 시 실시간 최신 정보 스크립트 자동 생성 연동 지원
- **교훈**: 사용자가 체감하는 가치는 '내용의 정확성과 전문성'에 있으므로, 동적 입력 파이프라인은 항상 도메인 지식 데이터베이스와 결합되어 있어야 함.
- **클러스터**: C (검증 누락)

### 2026-08-25 — [A] Windows 환경에서 FFmpeg/Subprocess 호출 시 CP949 인코딩 충돌로 인한 NoneType 오류

- **상황**: 텔레그램 봇으로 `/make` 요청 시 FFmpeg 출력 파싱 중 `expected string or bytes-like object, got 'NoneType'` 발생
- **잘못된 판단**: `subprocess.run(..., text=True)`가 Windows에서 기본 `cp949`로 디코딩을 시도함을 간과
- **5 Whys 근본 원인**:
  1. 왜 NoneType 에러가 났나? → `res.stderr`가 `None`으로 반환됨
  2. 왜 `res.stderr`가 `None`이었나? → 백그라운드 `_readerthread`가 `UnicodeDecodeError`로 중단됨
  3. 왜 `UnicodeDecodeError`가 났나? → FFmpeg의 UTF-8 한글 폰트/경로 바이트를 `cp949`로 디코드 시도
  4. 왜 `cp949`로 디코드했나? → `subprocess.run`에 `encoding="utf-8", errors="replace"`를 명시하지 않음
  5. 왜 누락되었나? → Linux(UTF-8 기본) 환경 중심의 스크립트 작성 습관
- **교훈**: Windows 환경의 모든 Subprocess 및 콘솔 I/O는 `encoding="utf-8", errors="replace"`와 `sys.stdout.reconfigure(encoding='utf-8')`를 필수 적용한다.
- **향후 적용 규칙**: 멀티미디어 및 외부 CLI 도구 연동 시 인코딩 매개변수 명시 표준화
- **클러스터**: A (전제 조건 미확인)
