# 학습 기록 (Lessons Learned)

> AI가 실수하거나 새로운 인사이트를 발견하면 여기에 기록합니다.
> 새 세션 시작 시 이 파일을 먼저 읽어서 같은 실수를 반복하지 않습니다.
>
> **작성 규칙**: 5 Whys로 **근본 원인**까지 파고들 것. 증상 수정 금지.

---

## 근본 원인 클러스터 (Root Cause Clusters)

실수가 누적되면 아래 4개 클러스터 중 하나로 분류하여 패턴을 파악합니다:

- **A. 전제 조건 미확인**: 작업 대상의 현재 상태를 확인하지 않고 추정
- **B. 본질 회피**: 표면 요청만 수용하고 진짜 문제를 파고들지 않음
- **C. 검증 누락**: 결과물을 자체 검수 없이 납품
- **D. 커뮤니케이션 실패**: 확신도/근거/대안 없는 모호한 보고

## Seed 원칙 (2026-08-24 셋업 시 확정)

### [필수] 출처 기반 답변 원칙
- **상황**: HACCP/FSSC22000 컨설팅 사업 — 20년 경력 전문성이 핵심 자산
- **규칙**: 오픈채팅방/블로그/유튜브 모든 답변에 **출처 명시**
- **근거**: 전문성 = 추측이 아닌 근거. 틀린 정보 1건이 신뢰를 무너뜨림
- **적용**: 모르면 "확인 후 알려드릴게요". 추측 답변 절대 금지 (Zero-Inference)
- **클러스터**: A (전제 조건 미확인 방지)

### [필수] 톤앤매너 — 따뜻한 선생님
- **규칙**: 존댓말 + 친근 + 전문용어 후 반드시 "쉽게 말하면" 추가
- **금지**: "안녕하세요, 오늘은~" 서론 filler, "감사합니다" 마무리
- **적용**: 첫 문장부터 가치 전달. "오늘 하나만 기억하세요" 패턴
- **클러스터**: D (커뮤니케이션)

### [필수] 3대 병목에 집중
1. **구독자 정체** — 유튜브 50명에서 멈춤
2. **매출 연결 부재** — 콘텐츠 → 컨설팅 전환 동선 불명확
3. **영상 제작 시간** — 너무 오래 걸림
- **적용**: 모든 제안이 이 3가지 중 하나를 해소하는지 자문. 아니면 우선순위 후순위
- **클러스터**: B (본질 회피 방지)

## 기록

### 2026-04-08 — [A] 작업 대상의 배포 상태 미확인 후 잘못된 전제로 계획 수립

- **상황**: ai-ceo-os 레포 업그레이드 제안 시, "부트캠프 1기 수강생이 지금 이 레포를 받고 있다"는 가정으로 "공사 중 노출 리스크"를 근거로 스코프 축소를 제안.
- **CEO 정정**: "아직 배포 전"
- **잘못된 판단**: 배포 상태를 확인하지 않고 본사 부트캠프 일정에서 유추. 추정을 사실처럼 사용.
- **5 Whys 근본 원인**:
  1. 왜 잘못된 전제를 세웠나? → 본사 맥락(부트캠프 1기 운영 중)을 프로젝트 상태로 투사
  2. 왜 투사했나? → 작업 대상(ai-ceo-os)과 본사(에이나우)를 동일한 컨텍스트로 취급
  3. 왜 구분하지 못했나? → 작업 시작 전 "이 프로젝트는 지금 어떤 단계인가?" 질문을 스킵
  4. 왜 스킵했나? → 브리핑 단계에서 tasks/todo.md는 읽었지만, **레포 상태(배포됨/배포 전/폐기)를 따로 확인하는 체크포인트가 없었음**
  5. 왜 체크포인트가 없었나? → 세션 시작 프로토콜에 "대상 프로젝트의 현재 상태 확인" 단계가 빠져 있음

- **교훈**: 작업 대상의 상태 정보(배포 여부, 활성 사용자 여부, 버전 단계)를 **작업 판단 전에 반드시 1회 확인**할 것.

- **향후 적용 규칙**:
  1. 프로젝트성 작업을 시작할 때 **"이 프로젝트의 현재 상태는 무엇인가?"**를 체크리스트 최상단에 고정
  2. 상태를 추정할 수밖에 없는 경우 **"추정 전제: X"를 명시**하고 확신도 하향 조정
  3. 타이밍/노출/배포 리스크를 근거로 내세울 때는 반드시 **상태 확인을 선행**

- **클러스터**: A (전제 조건 미확인)
